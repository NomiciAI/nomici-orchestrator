# v0.1 Boundaries

## Purpose

This document resolves design tensions that should be settled before implementation goes deeper.

The goal is to keep Nomici honest: it should be a control plane and designer, not a hidden full multi-agent framework, while still being useful after installation.

## Gateway Agent, Not Native Agent

`native_agent` is not a v0.1 public kind.

v0.1 should use:

```yaml
agents:
  product_pm:
    kind: gateway_agent
    model: gpt
    role: Coordinate product, architecture, implementation, and review.
```

Meaning:

- A `gateway_agent` is executed by a minimal Gateway agent loop.
- The loop may call one model, apply instructions, request handoffs, call agent-as-tool adapters, and request Nomici-mediated tools.
- The loop must emit trace events.
- All side-effecting tools still go through Policy, Approval, and Trace.
- The loop is not durable execution.
- The loop is not a general agent framework.
- Complex, stateful, long-running, framework-native behavior belongs in external runtimes.

Why this is acceptable:

- Nomici needs a small built-in coordinator for first-run useful packs.
- Calling it `native_agent` hides the tradeoff.
- Calling it `gateway_agent` makes the execution boundary explicit.

Agent kinds for v0.1:

- `gateway_agent`
- `external_agent`
- `model_agent`
- `tool_agent`

Reserved or future kinds:

- `native_agent`
- `remote_a2a_agent`
- `router_agent`
- `approval_agent`
- `memory_agent`

## Scope Tiers

The implementation plan should distinguish hard delivery from degradable delivery.

Hard proof slice:

```text
provider setup
  -> OpenAI-compatible or Ollama model profile
  -> one Gateway-mediated invocation
  -> trace event storage
  -> secret redaction
  -> health/status visibility
```

This proves Gateway, provider setup, adapter invocation, storage, trace, and security defaults.

Developer proof slice:

```text
cli_agent runtime
  -> external_agent invocation
  -> workspace diff capture
  -> trace event storage
  -> approval gate before publish actions
```

This proof slice can land before `gateway_agent` is useful. It proves Nomici's control-plane value by coordinating and governing agents users already run locally.

v0.1 product slice:

```text
provider setup
  -> pack inspect/install
  -> AgentGraph compile
  -> runtime or model/agent invocation
  -> run trace
  -> policy decision
  -> approval or artifact review where relevant
```

Degradable features:

- full Console setup wizard
- multi-agent canvas editing
- rich runtime reconciler automation
- non-trivial approval scopes
- full MCP proxy
- full A2A sidecars
- office/browser tool packs
- signed remote pack distribution

Hard features should not depend on degradable features.

## AgentGraph IR Convergence

AgentGraph IR is an internal target architecture, not an implementation mandate for the first adapter.

Implementation rule:

- Start with the smallest graph snapshot needed to run the proof slice.
- Add IR fields only when an adapter, pack, policy check, trace view, or Console feature needs them.
- Keep source mapping and immutable snapshots early because they affect errors, audit, and replay.
- Do not expose IR as a public standard in v0.1.

The OpenAI-compatible adapter should be the first reality check for IR shape.

It should force decisions around:

- streaming
- cancellation
- endpoint errors
- auth errors
- model capability mismatch
- trace payload shape
- token/cost metadata

## Gateway API Envelope

General command/query APIs should use the response envelope:

```json
{
  "data": {},
  "warnings": [],
  "request_id": "req_01H"
}
```

`GET /api/health` is a deliberate exception.

It may return a minimal naked health response because health probes, curl checks, process supervisors, and release smoke tests should not need the full Nomici API envelope.

Rules:

- `/api/health` is for liveness/readiness.
- Future `/api/status` or `/api/system/status` can use the normal envelope.
- Gateway API docs must state this exception explicitly.
- All non-health errors should use the standard error envelope.

## Pack Trust Before Signatures

`trust.level: official` in a local pack manifest is not authoritative in v0.1.

Until signed distribution exists:

- official packs are only packs bundled with the Nomici binary or listed in a compiled official pack index
- local directory packs are treated as `local` or `untrusted`
- manifest `trust.level` from local packs is informational or ignored
- Console may display "claims official" only as a warning, not as trust
- pack install must still show permissions and require review

The `trust` field can remain in the manifest as reserved metadata, but Gateway must not grant privileges based on it.

## Console Bootstrap

Console is served by Gateway. Therefore Console setup cannot exist before some Gateway process is running.

v0.1 should support two paths:

CLI-first path:

```text
nomici doctor
nomici model setup
nomici pack install developer-team
nomici up
nomici gateway open
```

Gateway-first path:

```text
nomici gateway run --setup
open http://127.0.0.1:8787
```

`--setup` is a bootstrap mode:

- serves Console
- exposes health, setup, provider, model test, pack inspect, and pack install APIs
- does not start runtimes automatically
- does not run agents
- uses the same token/auth/redaction model as normal Gateway

If bootstrap mode is not implemented in the first product slice, the hard v0.1 setup path is CLI-first and Console setup is degradable.

## Invariants

- `gateway_agent` is intentionally minimal.
- External runtimes remain the path for advanced agent behavior.
- The proof slice must run without pack registry, full canvas, durable execution, A2A sidecars, or MCP proxy.
- `official` trust requires an actual trust root.
- Health endpoint shape is a documented exception, not accidental drift.
- Console cannot bypass Gateway to mutate state.
- Claude Code, Codex, opencode, Aider, Cline, Continue, and similar local agents are external runtimes, not competitors to rebuild.
- CLI agent runtime profiles must default to untrusted policy and explicit workspace boundaries.
